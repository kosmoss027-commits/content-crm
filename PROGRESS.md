## Этап 1. Каркас — сделано локально, ждёт проверки и деплоя

### Что работает
- Вход по email + пароль, вход через Google, подтверждение email, восстановление пароля (Supabase Auth).
- При первом входе создаётся «Моё пространство» с проектом «Мой блог», пользователь — владелец.
- Рабочие пространства, проекты, роли (владелец / менеджер / ассистент / SMM).
- Левое меню со всеми разделами ТЗ, разделы будущих этапов — пустые экраны с пометкой «Этап N».
- Переключатель проектов в шапке (по всем пространствам пользователя), запоминает последний проект.
- Поиск и «+ Публикация» в шапке — заглушки до этапов 4–5.
- «Команда»: список участников, смена роли, удаление, приглашение по ссылке (действует 7 дней, только для указанного email).
- «Настройки» (только владелец): название пространства, проекты (создать, переименовать, цвет, архив/восстановление), тариф и лимиты.
- Тёмная тема по умолчанию, светлая — в меню пользователя. Мобильная версия: меню выезжает слева.
- Тестовые данные: `npm run db:seed` — 2 пространства, 4 проекта, 4 пользователя с разными ролями.
- 18 автотестов (`npm test`): изоляция данных между пространствами, права ролей, приглашения, первый вход, защита редиректа.

### Принятые решения
- **Стек:** Next.js 16 (App Router) + TypeScript, Prisma 7 + PostgreSQL (Supabase), Supabase Auth, Tailwind 4 + shadcn/ui, хостинг Railway.
- **Изоляция данных — в коде, а не через RLS.** Prisma подключается к базе ролью, которая обходит RLS Supabase. Поэтому весь доступ к данным идёт через `lib/db/*`: каждая функция получает контекст (`getProjectContext` / `getWorkspaceContext`), который проверяет членство, и фильтрует запросы по `workspaceId`, а не по id из URL. Чужой проект отдаёт 404. Покрыто тестами `tests/isolation.test.ts`.
- **Права ролей** в одном месте: `lib/auth/permissions.ts`. Разделы и их доступ — `lib/navigation.ts`.
  - Владелец — всё. Менеджер — сводка, кодовые слова, заявки, клиенты, задачи, команда (просмотр). Ассистент и SMM — контент-завод, контент-план, статистика, прогревы, сводка, задачи, команда (просмотр).
- **Тарифные лимиты** в одном месте: `config/plans.ts` («Старт»: 5 проектов, 5 участников, 100 аккаунтов в разведке, 300 разборов в месяц). Сменить тариф пространства пока можно только в базе (поле `Workspace.plan`).
- **Приглашения** пока без отправки писем: владелец копирует ссылку. Письма подключим, когда будет почтовый сервис (Resend и т. п.).
- **Cache Components в Next.js 16 выключены** (`next.config.ts`): все страницы зависят от вошедшего пользователя.
- **Локальная база** без Docker: `npm run db:local` поднимает встроенный PostgreSQL (`embedded-postgres`). `prisma dev` на Windows падает.
- **Вход для разработки:** `DEV_AUTH=1` в `.env` — выбор тестового пользователя без Supabase. В production не работает.

### Как запустить локально
```
npm install
npm run db:local        # в отдельном окне, держать открытым
npm run db:migrate      # создать таблицы
npm run db:seed         # тестовые данные
npm run dev             # http://localhost:3000
npm test                # автотесты
```
